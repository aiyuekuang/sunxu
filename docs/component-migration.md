# 组件盘点与迁移规范

## 当前 MES 范围

Sunxu 已完整迁入 MES 基线固定提交 `e92d02d7cf2269cf8c564a60ff6a00255e903c8e` 的两类组件：`src/components/**` 共享目录 88 个，以及 `src/screens/**/components/**` 页面私有目录 305 个。每个来源路径都在 [`MES 组件迁移清单`](./migrations/mes-components.md) 和逐文件 JSON 清单中有目标去向。来源工作区当时有未提交修改，只采用固定提交中的内容。

页面私有组件保存到 `src/mes/screens/**` 并保留内部边界；不会因为迁入就自动成为 Sunxu 公共 API。共享组件按职责进入 core、MES 领域或宿主集成子路径。CRM 组件仍须按来源提交独立盘点，不能将 MES 结果当成 CRM 迁移记录。

## 目标结构

```text
src/
  core/          # 跨业务 UI、tokens、通用交互和工具
  mes/           # MES 领域组件、私有页面组件和宿主契约
  integrations/  # 需要宿主生命周期或平台能力的显式集成
```

默认维护一个私有 `sunxu` 包，通过 `sunxu/core`、`sunxu/mes` 和 `sunxu/integrations/mes-app` 明确导入边界。页面私有组件不放入公开 barrel。发布节奏或兼容性确有需要时再考虑拆包。

## 迁移与依赖边界

- 来源清单应包含来源路径、固定提交、文件摘要、名称、层级、目标路径、导出子路径、宿主依赖、适配方式、迁移状态和验证证据。
- 依据真实调用和数据依赖归类。`common` 目录不代表组件一定通用；也不能让 core 反向依赖 MES 领域代码。
- API、Store、授权结果、导航上下文、实时事件、文件下载和宿主配置通过显式契约提供。共享组件不得保留来源 App 的 `@/` 路径或私有客户端依赖。
- 权限组件只消费宿主传入的授权结果或回调，不复制后端权限码和授权规则。
- App 更新、热更新、发布历史等功能必须隔离到宿主集成路径，导入公共 UI 时不触发网络请求、监听注册或私有配置读取。
- 新第三方依赖须有明确组件依据，并在 `peerDependencies`、可选 peer 或开发依赖中准确声明；不要复制 App 的完整依赖清单。

## 验证与公开发布

类型检查不能代替 UI 验收。UI 组件应在真实路由、适用视口和相关数据状态中渲染，并记录截图及 DOM 几何/溢出信息；缺少证据时标记 `UNVERIFIED`。

来源仓库无明确许可证时，不推断代码可再分发。公开发布前记录权利人授权和选定许可证，并核对第三方运行时依赖、图标、字体、图片和复制代码的许可证与归属。当前 MES 迁移保持包为私有且未发布。
