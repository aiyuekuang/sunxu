# 组件盘点与迁移计划

## 目标

把 MES App 基线的现有组件完整纳入 Sunxu 的迁移范围，同时收录东建 CRM 中可复用的组件。迁移结果按组件职责分层：跨业务基础组件、MES 领域组件、CRM 领域组件和宿主 App 集成组件。

本计划用于建立完整去向和依赖关系，不表示组件已经迁完，也不授权公开发布源代码。

## 来源

| 来源 | 位置 | 处理要求 |
| --- | --- | --- |
| MES App 基线 | `../mes-app/src/components/**` | 完整盘点；所有组件/模块均在清单中有目标去向或有理由的处理结论。遵守 MES 基线仓自身说明，迁移前固定提交。 |
| MES 页面目录 | `../mes-app/src/screens/**/components/**` | 盘点复用范围、领域语义和 App 依赖；可复用组件或用户明确要求纳入的组件进入迁移清单，页面编排保持为示例或在来源 App 中。 |
| 东建 CRM App | `../dongjian-crm/src/components/**` | 完整盘点；区分通用组件、CRM 领域组件和宿主集成，保留 CRM 业务语义。 |
| CRM 页面目录 | `../dongjian-crm/src/screens/**/components/**` | 盘点可复用模块，不能把整页或只服务单个页面的业务编排伪装成基础组件。 |

## 目标结构建议

开始迁移后，按真实依赖确定路径。可从以下边界起步，后续根据清单调整：

```text
src/
  core/          # 跨业务的基础 UI、tokens 和通用交互
  mes/           # MES 领域组件；保留明确的 MES 语义
  crm/           # CRM 领域组件；保留明确的 CRM 语义
  integrations/  # 显式宿主 adapter；不从基础入口自动加载副作用
examples/
  expo/          # 可运行的组件示例和人工视觉检查入口
```

优先采用单一无 scope npm 包 `sunxu`，由 `sunxu`、`sunxu/mes`、`sunxu/crm` 等明确子路径区分 API。只有依赖闭包或发布节奏迫使分包时，再提出多包方案及理由。

## 迁移清单格式

每次迁移都在下表追加或链接完整清单；大型模块可拆成独立文件。禁止仅记录“目录已复制”。

| 来源提交 | 来源路径 | 名称 | 层级 | 目标路径 / 导出 | 宿主依赖 | 适配方式 | 状态 | 验证证据 / 未决项 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待固定 | 待盘点 | 待盘点 | core / mes / crm / integration | 待定 | 待盘点 | 待评审 | NOT STARTED | 待补充 |

状态使用 `NOT STARTED`、`IN PROGRESS`、`MIGRATED`、`VERIFIED` 或 `EXCLUDED WITH REASON`。每个来源组件必须有记录；不适合成为 Sunxu 可复用 API 的项目也要留下明确理由和替代位置。

## 迁移步骤

1. **固定来源快照**：记录两个仓库的分支、完整提交号和工作区状态。选定来源后不要依赖“最新版本”这样的浮动指针。
2. **建立完整清单**：枚举来源目录组件，搜索所有导入点、别名导入、动态注册、Provider 包装和依赖副作用；给每个条目分类。
3. **追依赖闭包**：对组件使用的主题、工具、hook、类型、资源和运行时模块逐项归类；不复制无关 App 目录、构建产物或整个依赖清单。
4. **分层迁入**：先确定 core 的 tokens、主题和基础组件，再迁入 MES/CRM 领域组件与必要的显式 adapter；维护清晰导出，避免跨域循环依赖。
5. **解耦宿主**：将 API、权限、导航、Store、服务端业务规则和私有配置改为宿主契约。展示状态与回调行为由组件提供；最终数据和授权由宿主负责。
6. **形成消费示例**：在 Expo 示例工程展示安装后的公开导入方式、Provider 初始化、组件主要状态和领域 adapter 接法。示例不得包含生产密钥或真实业务数据。
7. **逐项验证并回写记录**：验证构建/类型/API 使用方式；UI 组件在示例或宿主真实渲染检查。尚未实际渲染的项目标记 `UNVERIFIED`。
8. **公开发布前核准授权**：记录来源代码权利确认、选定许可证、第三方资源与依赖许可证、npm 包内容检查。此项未完成时保持不发布。

## 公开发布前的阻塞项

截至初始化检查，MES App 和 CRM App 来源仓库根目录都未发现 `LICENSE` 文件。公开发布前必须由权利人确认代码可再分发并确定本项目许可证；还要检查各资源与第三方组件的许可证。不能把 npm 名称未占用当作代码有开源授权的证明。
